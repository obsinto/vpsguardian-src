┌─────────────────────────────────────────────────────────────┐
│  CENÁRIO 2: Restaurar Banco Após Problema                  │
└─────────────────────────────────────────────────────────────┘

Menu → 2 → 7
         ▲
         └─ Restaurar Banco Específico

Fluxo:
1. Confirmar operação crítica (digitar "SIM")
2. Listar backups disponíveis
3. Escolher banco para restaurar
4. Restauração inteligente:
   ├─► Tentar volume snapshot (rápido)
   ├─► Validar se funcionou
   ├─► Se crash loop → Rollback
   └─► Fallback para SQL dump
5. Validação automática de saúde

Resultado:
✅ Banco restaurado
✅ Container rodando
✅ Integridade validada


┌─────────────────────────────────────────────────────────────┐
│  CENÁRIO 3: Validação Pós-Migração                         │
└─────────────────────────────────────────────────────────────┘

Menu → 2 → 8
         ▲
         └─ Validar Saúde dos Bancos

Testes executados:
✓ PostgreSQL: pg_isready + query test
✓ MySQL: mysqladmin ping + mysqlcheck
✓ MongoDB: ping + listDatabases
✓ Redis: PING + DBSIZE

Resultado:
✅ Relatório de saúde
✅ Problemas detectados (se houver)
✅ Recomendações de correção

🔴 RESTAURAR BANCO (Opção 7):
   • OPERAÇÃO DESTRUTIVA - Dados atuais serão perdidos
   • Requer confirmação crítica (digitar "SIM")
   • Causa downtime das aplicações
   • Sempre faça backup antes de restaurar

🟢 VALIDAR SAÚDE (Opção 8):
   • OPERAÇÃO SEGURA - Apenas leitura
   • Não altera dados
   • Pode ser executado a qualquer momento
   • Útil para diagnóstico

╔═══════════════════════════════════════════════════════════════╗
║                    🔧 SOLUÇÃO DE PROBLEMAS                    ║
╚═══════════════════════════════════════════════════════════════╝

❓ "Script não encontrado"
   → Verifique se os scripts estão em:
     /opt/vpsguardian/migrar/restore-database-volumes.sh
     /opt/vpsguardian/scripts-auxiliares/validate-database-health.sh

❓ "Permission denied"
   → Execute com sudo:
     sudo /opt/vpsguardian/menu-principal.sh

❓ "Banco não está saudável após restore"
   → Execute validação:
     Menu → 2 → 8
   → Verifique logs:
     docker logs CONTAINER_NAME

❓ "Crash loop detectado"
   → Script fará rollback automático para SQL dump
   → Aguarde conclusão
   → Verifique logs em /var/log/manutencao/
